## ベイズの定理とは

「検査で陽性が出た。本当に病気である確率は？」——直感では「検査の感度（当たる率）」とほぼ同じだと感じます。ところが、感度 99% の検査でも、答えが **17%** にしかならないことがあります。この一見奇妙な結果を正確に計算するのが **ベイズの定理** です。

$$
P(A\mid B) = \frac{P(B\mid A)\,P(A)}{P(B)}
$$

- $P(A)$：**事前確率**（証拠を見る前の確率。例：その病気の有病率）
- $P(B\mid A)$：**尤度**（病気のとき陽性になる率 = 感度・真陽性率）
- $P(A\mid B)$：**事後確率**（陽性という証拠を得た後の、病気である確率 = 陽性的中率 PPV）

分母 $P(B)$ は「検査が陽性になる全体の確率」で、全確率の法則から組み立てます：

$$
P(B) = P(B\mid A)\,P(A) + P(B\mid \neg A)\,P(\neg A)
$$

ここで $P(B\mid \neg A)$ は **偽陽性率**（病気でないのに陽性になる率）です。この記事では、

1. 「基準率の誤謬」がなぜ起きるかを数式と人数で
2. 20 行の JavaScript でのベイズ更新の実装
3. 感度・偽陽性率を動かしたときの事後確率の振る舞い

を、実際の数値で確かめていきます。

## 基準率の誤謬を人数で見る

ツールの「希少疾患検査」プリセットは、有病率 $P(A)=1\%$、感度 $P(B\mid A)=99\%$、偽陽性率 $P(B\mid\neg A)=5\%$ です。1000 人の集団で何が起きるか数えてみます。

| 区分 | 人数 | 内訳 |
|---|---|---|
| 病気（10 人）→ 陽性（TP） | 約 10 人 | $1000\times0.01\times0.99$ |
| 病気（10 人）→ 陰性（FN） | 約 0 人 | $1000\times0.01\times0.01$ |
| 健康（990 人）→ 陽性（FP） | 約 50 人 | $1000\times0.99\times0.05$ |
| 健康（990 人）→ 陰性（TN） | 約 940 人 | $1000\times0.99\times0.95$ |

陽性になったのは合計 $10+50 = 60$ 人。そのうち本当に病気なのは 10 人だけ。つまり、

$$
P(A\mid B) = \frac{10}{10+50} \approx 16.7\%
$$

感度が 99% もあるのに、陽性的中率は **17% 程度**。理由は単純で、健康な人（990 人）の母数が圧倒的に多いため、偽陽性の **絶対数**（50 人）が真陽性（10 人）を上回るからです。事前確率（基準率）を無視して感度だけを見る誤りを **基準率の誤謬（base-rate fallacy）** と呼びます。

## 20 行のベイズ更新

ベイズの定理そのものは数行です。NovaSolver のツールが内部で回しているのと同じロジックを書き出します：

```javascript
// 事前確率 PA、感度 PBA、偽陽性率 PBNA からベイズ更新
function bayesUpdate(PA, PBA, PBNA) {
  // 全確率の法則で「検査が陽性になる確率」P(B)
  const PB = PBA * PA + PBNA * (1 - PA);

  // 事後確率（陽性的中率 PPV）
  const posterior = (PBA * PA) / PB;

  // ベイズ係数 K（証拠の強さ。事前確率に依存しない）
  const bayesFactor = PBA / PBNA;

  // 陰性的中率 NPV = P(¬A|¬B)
  const pNotB = (1 - PBA) * PA + (1 - PBNA) * (1 - PA);
  const npv = ((1 - PBNA) * (1 - PA)) / pNotB;

  return { PB, posterior, bayesFactor, npv };
}

const r = bayesUpdate(0.01, 0.99, 0.05);
console.log((r.posterior * 100).toFixed(1) + '%'); // 16.7%
console.log('K =', r.bayesFactor.toFixed(1));       // K = 19.8
```

ベイズ更新の便利な点は、**事後確率を次の事前確率として使い回せる** ことです。同じ検査を 2 回受けて両方陽性なら、1 回目の事後確率 16.7% を 2 回目の事前確率に代入すると、

$$
P(A) = 0.167 \;\Rightarrow\; P(A\mid B) = \frac{0.99\times0.167}{0.99\times0.167 + 0.05\times0.833} \approx 79.9\%
$$

と一気に跳ね上がります。証拠が積み重なるほど確信が強まる、これがオンライン学習やスパムフィルタの基本原理です。

## 事前確率で事後確率がどう動くか

NovaSolver のツールには「事前→事後」タブがあり、感度・偽陽性率を固定したまま事前確率 $P(A)$ を 0〜100% で動かしたときの事後確率曲線を描けます。感度 99% / 偽陽性率 5% で計算すると、典型的には下のような S 字（ロジスティック）型になります：

![事前確率と事後確率の関係（ベイズ更新曲線）](/images/bayes-theorem-visual/charts-closeup.png)

特徴：

- **事前確率が低い領域（左端）では事後確率も低く張り付く**：希少疾患スクリーニングが難しい本質
- 事前確率が中程度に上がると事後確率が急上昇する
- 偽陽性率が小さいほど曲線が左に寄り、低い事前確率でも高い的中率になる

## プリセットごとの数値を比べる

4 つのプリセットで事後確率（PPV）とベイズ係数 K を計算すると、事前確率と偽陽性率の効きがはっきりします：

| プリセット | $P(A)$ | 感度 | 偽陽性率 | 事後確率 PPV | K |
|---|---|---|---|---|---|
| 希少疾患検査 | 1% | 99% | 5% | **16.7%** | 19.8 |
| 一般検診 | 30% | 90% | 10% | 79.4% | 9.0 |
| 精密検査 | 50% | 95% | 2% | 97.9% | 47.5 |
| スパムフィルタ | 0.1% | 99% | 1% | **9.0%** | 99.0 |

注目すべきは「スパムフィルタ」。ベイズ係数 K = 99 と証拠は極めて強いのに、事前確率がたった 0.1% なので 1 回の判定では PPV が 9% に留まります。だからスパム判定は単語ごとに何度もベイズ更新を重ねて確信を高めます。逆に「精密検査」は事前確率 50%・偽陽性率 2% なので、1 回で 98% に達します。事前確率と偽陽性率を下げることがいかに重要かが分かります。

## まとめ

- ベイズの定理 $P(A\mid B)=P(B\mid A)P(A)/P(B)$ は、証拠を得たあとの確率を更新する式
- 感度 99% の検査でも、有病率 1%・偽陽性率 5% なら陽性的中率は約 17%（基準率の誤謬）
- 1000 人で数えると、真陽性 10 人に対し偽陽性 50 人 → $10/60\approx16.7\%$ と一致
- 事後確率を次の事前確率に使えば証拠を積み重ねられる（2 回陽性で約 80%）
- 事前確率と偽陽性率を下げることが、的中率を上げる鍵

ベイズの考え方は、医療診断だけでなく、機械学習のオンライン学習や、計算結果と実験を突き合わせてモデルの不確かさを更新する手法（UQ）にも共通する、確率的思考の土台です。
