## 連続PIDをそのままマイコンに載せると何が起きるか

教科書のPID制御は連続時間の式で書かれます：

$$
u(t) = K_p\, e(t) + \frac{K_p}{T_i}\int_0^t e(\tau)\,d\tau + K_p T_d \frac{de(t)}{dt}
$$

ところが実機のPLCやマイコンは、一定の**サンプリング周期 $T_s$** ごとにしかセンサを読めず、出力も更新できません。つまり連続の積分・微分を、和と差分で近似する必要があります。この「連続→離散」への置き換えが**離散化（discretization）**です。

問題は、$T_s$ の選び方しだいで挙動が大きく変わること。$T_s$ を細かくすればよい、というわけでもありません。この記事では、

1. 連続PIDの離散化式と、各係数が $T_s$ にどう依存するか
2. 約25行のJavaScriptで書ける離散PID
3. $T_s$ を粗くしたときに応答が崩れていく様子を数値で確かめる

を扱います。

## 離散化の基本式

最も素直なのは、積分を「誤差の足し上げ × $T_s$」、微分を「前回との差 ÷ $T_s$」で近似する方法です（前進・後退差分）。離散時刻 $k$ における制御量 $u[k]$ は：

$$
u[k] = K_p\, e[k] + K_i T_s \sum_{j=0}^{k} e[j] + K_d \frac{e[k]-e[k-1]}{T_s}
$$

ここで $K_i = K_p/T_i$、$K_d = K_p T_d$ です。シミュレーターはこの式をそのまま実装しており、画面の「離散積分係数」「離散微分係数」として次の値を表示します：

| 表示 | 定義 | $T_s$ 依存 |
|---|---|---|
| 離散積分係数 $k_i$ | $K_p T_s / T_i$ | $T_s$ に**比例** |
| 離散微分係数 $k_d$ | $K_p T_d / T_s$ | $T_s$ に**反比例** |

積分項は1ステップあたり $T_s$ だけ足すので $T_s$ が大きいほど大きく、微分項は $T_s$ で割るので $T_s$ が小さいほど大きくなります。**この非対称性が離散化のすべての肝**です。

## 係数を実際に計算してみる

デフォルト値 $K_p=2.5,\ T_i=1.8\,\text{s},\ T_d=0.25\,\text{s},\ T_s=0.05\,\text{s}$、微分フィルタ係数 $N=12$ で、ツールの出力式を再現すると：

$$
k_i = \frac{K_p T_s}{T_i} = \frac{2.5 \times 0.05}{1.8} = 0.069
$$
$$
k_d = \frac{K_p T_d}{T_s} = \frac{2.5 \times 0.25}{0.05} = 12.5
$$

サンプル遅れ目安は $T_s \cdot 180/(T_i\pi) \approx 1.6^\circ$、微分ノイズ倍率は $1 + k_d/N = 1 + 12.5/12 = 2.04$ 倍。いずれもツールの表示と一致します。

ここで注目すべきは $k_d$ の振る舞いです。$T_s$ を半分の $0.025\,\text{s}$ にすると $k_d=25.0$、$0.005\,\text{s}$ なら $k_d=125$ と、**$T_s$ を細かくするほど微分係数が際限なく膨らみます**。微分はセンサノイズをそのまま増幅するため、サンプリングを速くするだけでは逆にノイズに弱くなる——これが微分項に必ずフィルタを入れる理由です。

## 25行のJavaScript実装

離散PIDは状態（積分の累積と前回誤差）を持つだけで、驚くほど短く書けます。1次系プラント $G(s)=K/(\tau s+1)$ をZOH離散化して閉ループで回します：

```javascript
const Kp = 2.5, Ti = 1.8, Td = 0.25;   // 連続PIDゲイン
const Ki = Kp / Ti, Kd = Kp * Td;       // 換算
const K = 1.0, tau = 1.0;               // プラント

function simulate(Ts, tEnd = 12) {
  const ad = Math.exp(-Ts / tau), bd = K * (1 - ad);
  let y = 0, sum = 0, ePrev = 0;        // 出力・積分累積・前回誤差
  const log = [];
  for (let k = 0; k * Ts <= tEnd; k++) {
    const e = 1.0 - y;                   // 目標値1へのステップ
    sum += e;                            // 誤差を足し上げる
    const u = Kp * e                     // 比例
            + Ki * Ts * sum              // 積分(× Ts)
            + Kd * (e - ePrev) / Ts;     // 微分(÷ Ts)
    y = ad * y + bd * u;                 // プラントを1ステップ進める
    ePrev = e;
    log.push([k * Ts, y]);
  }
  return log;
}
```

$T_s$ を引数にしているのがポイントで、同じゲインのまま $T_s$ だけを変えて応答を比較できます。

## サンプリングを粗くすると応答が崩れる

上の `simulate()` で $T_s$ を変えてオーバーシュート（行き過ぎ量）を測ると、はっきりした傾向が出ます：

| $T_s$ [s] | オーバーシュート | 挙動 |
|---|---|---|
| 0.05 | $\approx 0\%$ | なめらかに整定 |
| 0.20 | $8.5\%$ | わずかに振動 |
| 0.26 | $33\%$ | 大きく振動しつつ収束 |
| 0.30 | $168\%$ | 発散気味 |
| 0.50 | 発散 | 不安定 |

連続設計では安定だった同じゲインが、$T_s$ を大きくしただけで振動し、ついには不安定化します。離散化は実質的に**むだ時間（位相遅れ）**を持ち込み、これが位相余裕を食いつぶすからです。実務で「制御対象の時定数の $1/10$ 以下に $T_s$ を取る」と言われるのはこのため。今回の $\tau=1\,\text{s}$ なら $T_s \lesssim 0.1\,\text{s}$ が目安で、表の結果ともよく合います。

## 注意点：単一の数値で決めない

> ツールの「微分ノイズ倍率」は $1 + (K_p T_d / T_s)/N$ という簡易式で、$T_s$ を小さくするほど大きくなります。これは「速いサンプリングは微分ノイズに弱い」という正しい性質を表していますが、**位相遅れ（むだ時間）の観点では逆に $T_s$ が大きいほど悪化**します。つまりノイズと安定性は $T_s$ に対して反対方向に効くため、最適点はその中間にあります。

実装ではこの簡易モデルに加えて、積分の飽和（アンチワインドアップ）、出力の量子化、サンプリングジッターも効いてきます。最終判断は実測・詳細解析・メーカー条件で確認してください。

## まとめ

- 連続PIDの離散化は、積分を $K_i T_s\sum e$、微分を $K_d (e[k]-e[k-1])/T_s$ で近似する
- $k_i \propto T_s$、$k_d \propto 1/T_s$ という非対称性が本質。デフォルトで $k_i=0.069,\ k_d=12.5$
- $T_s$ を細かくすると微分係数が膨れてノイズに弱くなり、粗くすると位相遅れで不安定化する
- 同じゲインでも $T_s=0.05$ は整定、$T_s=0.30$ では発散——$T_s$ は立派な設計変数

「教科書のゲインをそのまま載せたのに振動する」の多くは離散化の理解不足が原因です。$T_s$ を1つの設計パラメータとして扱う感覚が、デジタル制御では欠かせません。
