## Bloom フィルタとは

**Bloom フィルタ** は「ある要素が集合に含まれているか？」を、ごく小さなメモリで高速に判定する確率的データ構造です。要素そのものを保存せず、$m$ ビットのビット配列と $k$ 個のハッシュ関数だけを使います。

- 要素を登録するとき：$k$ 個のハッシュ値が指すビットを全部 1 にする
- 要素を問い合わせるとき：$k$ 個のビットが全部 1 なら「たぶん含まれる」、1 つでも 0 なら「確実に含まれない」

ここがポイントで、Bloom フィルタは **偽陰性（含まれているのに「ない」と答える）を絶対に出しません**。その代わり、偶然すべてのビットが他の要素で 1 になっていると、含まれていないのに「ある」と答えてしまう——これが **偽陽性（false positive）** です。

この記事では：

1. 偽陽性率 $p$ を決める式と、最適ハッシュ数 $k_{opt}$
2. 20 行ほどの JavaScript による偽陽性率の計算
3. ハッシュ数 $k$ に「ちょうどいい値」が存在することを数値で確かめる

## 偽陽性率と最適ハッシュ数

$n$ 個の要素を登録したあと、あるビットが 0 のままである確率は $\left(1-\frac{1}{m}\right)^{kn} \approx e^{-kn/m}$ です。よって 1 であるビットの割合（ビット占有率）は $1-e^{-kn/m}$。偽陽性は $k$ 個のビットがすべて 1 のときに起きるので、偽陽性率は次式になります：

$$
p = \left(1 - e^{-kn/m}\right)^{k}
$$

$k$ を増やすと「ビットが 1 である確率」が上がる一方、「$k$ 個すべてが 1 になる難しさ」も上がります。この綱引きを微分して最小化すると、最適なハッシュ数が得られます：

$$
k_{opt} = \frac{m}{n}\ln 2
$$

このとき、ビット占有率はちょうど 50% になり、偽陽性率は $p \approx (1/2)^{k_{opt}} = 2^{-(m/n)\ln 2}$ まで下がります。つまり **1 要素あたりのビット数 $m/n$** が精度を決める主役で、$k$ はその比に合わせて選ぶ調整つまみ、という構図です。

## JavaScript で偽陽性率を計算する

式そのままで実装できます。NovaSolver のツールも同じ計算式（`expr`）で動いています：

```javascript
// 偽陽性率 p = (1 - e^(-kn/m))^k
function falsePositiveRate(n, m, k){
  return Math.pow(1 - Math.exp(-k * n / m), k);
}
// ビット占有率（1 のビットの割合）
function occupancy(n, m, k){
  return 1 - Math.exp(-k * n / m);
}
// 最適ハッシュ数 k_opt = (m/n) ln2
function optimalK(n, m){
  return (m / n) * Math.LN2;   // Math.LN2 = 0.6931...
}

// 例: n=50000 要素, m=800000 ビット, k=7
const n = 50000, m = 800000, k = 7;
console.log((falsePositiveRate(n, m, k) * 100).toFixed(3) + '%');  // 0.070%
console.log((occupancy(n, m, k) * 100).toFixed(1) + '%');          // 35.4%
console.log(optimalK(n, m).toFixed(2));                            // 11.09
```

この設定（1 要素あたり 16 ビット、$k=7$）では偽陽性率は **0.070%**、ビット占有率は **35.4%**。問い合わせを 100,000 回すると、期待される誤ヒットは $100{,}000 \times 0.00070 \approx 70$ 回です。最適ハッシュ数は 11.09 なので、$k$ をもう少し増やす余地があると分かります。

## ハッシュ数には「ちょうどいい値」がある

$m/n = 16$（$n=50000$, $m=800000$）に固定して $k$ を 1 から 16 まで振ると、偽陽性率はいったん下がってから再び上がる、谷形のカーブを描きます：

![ハッシュ数による偽陽性率の谷と曲線](/images/bloom-filter-false-positive/charts-closeup.png)

| ハッシュ数 $k$ | 偽陽性率 $p$ |
|---|---|
| 1 | 6.06% |
| 3 | 0.500% |
| 7 | 0.070% |
| 11 | **0.046%（最小付近）** |
| 14 | 0.053% |
| 16 | 0.065% |

最小は $k=11$ 付近で、これは式の $k_{opt}=16\ln 2 \approx 11.09$ とぴたり一致します。$k$ が少なすぎると「ビットが立っていない」隙間が多く、多すぎると「ビット配列がすぐ埋まる」ため、どちらに振れても偽陽性率は悪化します。

メモリ（$m/n$）を増やすと偽陽性率は指数的に改善します。最適 $k$ で比べると：

| $m/n$ | 最適 $k$ | 偽陽性率（最適時） |
|---|---|---|
| 8 | 6 | 2.16% |
| 10 | 7 | 0.82% |
| 16 | 11 | 0.046% |
| 20 | 14 | 0.007% |

1 要素あたり 8 ビットから 20 ビットへ増やすだけで、偽陽性率は約 300 分の 1 になります。

## まとめ

- Bloom フィルタは偽陰性ゼロ・小メモリで集合判定する確率的データ構造（代償が偽陽性）
- 偽陽性率は $p=(1-e^{-kn/m})^k$、最適ハッシュ数は $k_{opt}=(m/n)\ln 2$
- $k$ は谷形で、最適点（占有率 50%）を外すと両側で悪化する
- 精度を決める主役は 1 要素あたりのビット数 $m/n$。$8 \to 20$ ビットで偽陽性率は約 300 分の 1

削除やカウントが必要なら Counting Bloom filter など派生構造を検討します。本ツールは初期検討に役立ちますが、実運用ではハッシュ関数の質や実測値も併せて確認するのが安全です。
